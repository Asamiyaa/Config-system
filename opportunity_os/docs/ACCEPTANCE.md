## 四、未完成的验证与实际风险

- **外网：尚未完成端到端真实联网扫描验收。** 打包环境不能访问公网 DNS，所以不能宣称 GitHub/HN/X/RSS 的当前接口都已实际返回数据。用户部署后请进入“情报源中心”，检查每个来源是否成功或触发限流。
- **X：未提供可用开发者授权**，所以不会假装采集 X 内容；官方搜索可能需要付费额度。
- **阿里/火山 LLM：未提供合法 API Key**，所以模型分析尚未实际付费调用。
- **Windows：本轮仅交付启动与任务脚本**，未在 Windows 真机执行，建议按 README 验收一次。
- **信息可靠性：** GitHub stars、HN 评论是需求代理，不是经核实成交；所有商业报价均为测试假设。
- **生产部署：** 当前没有多用户登录、权限、企业审计、HTTPS 反向代理、分布式任务锁；必须先补齐这些能力才能直接公开发布 SaaS。
- **RSS 地址安全：** 增加了本机/内网 IP 输入初筛，但没有完整 DNS 重绑定防护，因此仍然仅建议本地可信用户使用。

## 五、建议第一次在 Windows 的验收步骤

1. 解压包，双击 `run_windows.bat`，确认浏览器打开本机 `http://127.0.0.1:8767`。
2. 查看控制台是否提示 `Uvicorn running`，浏览器左侧是否显示“本地服务运行正常”。
3. 点击「扫描新机会」，等待扫描完成，进入「情报源中心」，记录每一源的状态及真实新增条数。
4. 若 GitHub 失败但别的源正常，确认状态为 partial，并能继续浏览已成功采集的线索。
5. 在「机会雷达」选择真实项目，确认原始链接、许可证、证据记录、商业假设与评分。
6. 修改阶段与测试价格，刷新页面，确认更改持久化。
7. 添加验证实验并保存样例 *人工测试记录*，之后清理样例；如使用 DEMO，点击设置页删除体验数据。
8. 双击 `backup_windows.bat`，确认 `DATA_DIR/backups` 下出现新数据库副本。
9. 若要每天关掉网站继续定时扫描，运行 `install_daily_task.ps1`，在 Windows 任务计划程序中检查触发器/日志。
10. 再按需要配置 X/LLM 自有授权，单独验证其成功、限流和实际费用，不要预设免费。

**结论：核心单机软件功能、数据逻辑和 Web 交互在离线环境验证通过；网络/外部付费 API/Windows 计划任务仍需目标环境补验。**
