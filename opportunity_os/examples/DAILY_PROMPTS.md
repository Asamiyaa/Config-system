# 可以直接复制给 Agent 的使用范式

## 每日 Scout

> 根据 Opportunity OS 的当天新入库线索，筛选最值得研究的 5 个。逐项提供真实来源链接、日期、变化、许可证、可能客户、证据等级、风险和下一步实验。缺失/失败的来源必须明确说明，严禁虚构数据。

## 7 日收费试验

> 我选了机会 ID [填入]。先确认原始公开证据和已有客户记录，写出一个有明确失败标准的 7 天验证计划。产品能做什么、哪些做不到？建议使用哪三个渠道进行合规获客？每一步人工需要做什么？第七天根据什么数据决定停/走？

## 闲鱼服务草稿

> 为机会 ID [填入] 制作服务上架文案草稿，包括标题、实际可交付内容、需要客户提供的前置条件、预期耗时、测试报价、售后边界、许可证/第三方 API/账号说明。标记“尚未实现或尚未验证”的功能，不要发布或承诺成交。

## X 原创内容

> 基于某个实际测试过的 GitHub 项目，写三版展示其技术价值的原创短帖，必须指出测试平台、限制条件、源仓库、我的附加价值，不伪造测试结果。区分内容流量和真实商业线索。

## 周度经营复盘

> 汇总上周用户手工录入的真实联系人、有效回复、订单、收入、直接成本、每单工时，计算贡献利润及最大证据缺口。按继续/调整/归档建议排序，不要根据 GitHub stars 推断市场收入。
