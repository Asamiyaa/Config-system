# UI 案例拆解学习网站 · 使用说明

纯静态前端项目（HTML + Tailwind + 原生 JS，无后端、无服务器）。
固定流程：**上传截图 → AI 预解析（仅 5 个字段）→ 人工校对、补充场景与避坑 → 保存归档**。

---

## 一、启动方式（无需安装任何环境）

1. 打开文件夹 `E:\aiLearn`；
2. 双击 **`index.html`**，用任意现代浏览器（Chrome / Edge 等）打开即可；
3. 也可把 `index.html` 拖入浏览器窗口。

> 首次打开会自动加载 2 个内置示例案例（B 端仪表盘、C 端商品详情页）。

---

## 二、整体布局与页面

全站采用**左侧导航 + 右侧主内容区**，不再使用顶部导航条：

- **默认收缩为 64px 图标栏**：宽屏（>900px）下侧边栏只显示功能图标（案例画廊 / 案例对比 /
  提示词模板 / **设置**）、分组与底部新建图标，文字隐藏；**鼠标移到侧边栏即浮层展开为 248px**
  完整树形（不挤压主区），鼠标移开自动收回；
- 侧边栏按**分组**展示案例：内置“默认分组”，可新建/重命名/删除分组（默认分组不可删，删除其他组后
  其案例自动回到默认分组）；
- **拖拽管理**：拖动案例节点可在组内排序（按鼠标上下半区显示插入位置），也可跨组拖动归类，
  分组空白区拖放则移到该组末尾；
- 案例节点：点标题进入查看页；鼠标悬停时右侧出现**编辑小按钮**，可直接进入该案例编辑页（窄屏常显）；
- **操作按钮统一在主区右上角**：每页都有“新建案例”，进入某案例后还会出现“编辑案例”“导出Markdown”，
  不再占用侧边栏、也不会遮挡左下角；
- 窄屏（≤900px）侧边栏自动变为抽屉，点左上角悬浮汉堡按钮展开（窄屏不触发图标栏与 hover 浮层）。

| 页面 | 作用 |
| --- | --- |
| `index.html` | 案例画廊：卡片缩略图、搜索、标签筛选（样式/业务标签）、收藏、导入 JSON、右上角新建 |
| `view.html` | **只读查看页**：左图（相册切换/标注）右侧详细内容；**只显示有内容的区块，空框整框隐藏**；支持键盘 ↑/↓ 切换案例 |
| `editor.html` | **编辑页（与查看页独立）**：两栏，左=图片上传（紧凑留白）/相册/标注，右=AI 解析 5 块（默认展开）+ 人工场景与避坑 + 版本记录，**标签卡紧凑后置**；右下角悬浮“返回/保存归档” |
| `compare.html` | 选 2 个案例并排对比，支持两列同步滚动 |
| `template.html` | 提示词模板管理（内置 B 端、C 端两套模板，可增删改） |
| `settings.html` | **设置页**：AI 视觉接入配置、对案例执行 AI 解析、内容保存路径（目录授权直写） |

> 查看与编辑分离：画廊点卡片 → `view.html` 查看；点侧边栏“编辑案例” → `editor.html` 修改。
>
> **图片双击放大**：编辑页与查看页的主图、相册缩略图，双击即弹出全屏灯箱（大图 + 关闭按钮），
> 支持 ESC、点遮罩、点关闭按钮关闭。

## 三、测试指引：演示 AI 辅助录入完整流程

### 步骤 1：新建案例
点主区右上角（或侧边栏底部）的 **【新建案例】**，进入空白编辑器，在顶部输入案例标题。
右栏**最后的“标签”卡片**（紧凑样式）可编辑 **样式标签、业务标签**：输入后回车/逗号添加、点 x 删除；
下方候选区列出全部已有标签，**点击即可多选/取消**（已选高亮），无需重复输入。

> 查看与编辑是两个页面：画廊点卡片默认进入只读的 `view.html`（左图右内容、内容铺开）；
> 要修改时点查看页右上角 **【编辑案例】** 才进入 `editor.html`。

### 步骤 2：上传截图（左栏）
- 点击上传区选择图片，或**直接拖拽**图片到上传区；
- 也可先复制截图，再在页面按 **Ctrl+V 粘贴**；支持多图，点相册缩略图可切换当前图片。

### 步骤 3：图片标注（可选）
- 点 **【添加标注】**，然后在图片上点击要标注的位置；
- 在弹窗输入标注内容（如“顶部筛选区”），标注会以圆点 + 气泡显示，并记录百分比坐标。

### 步骤 4：AI 自动解析（执行入口在设置页）
- 编辑页的 **AI 解析 5 块默认全部展开**（布局结构、UI视觉风格、交互特征、色调与氛围、布局优点），
  页面上不再放“执行 AI 解析”按钮，全量解析统一在 **设置页** 触发；
- 打开 `settings.html`，在“对案例执行 AI 解析”选择案例与写入方式：**替换**（覆盖）或 **追加**（接在原文后）；
- 点 **【执行 AI 解析】**，等待后 5 个区块自动填充，并带浅蓝底 **【AI预生成】** 标记。
- 交互特征若无法判断动态行为，会自动加前缀：**“静态截图，动态交互需手动补充；”**。
- 编辑页每个区块右上角有 **【局部重生成】**，可单独刷新某一项。

### 步骤 5：人工校对与补充（布局优点下方）
- 直接修改任意 AI 内容，来源标记会自动从“AI预生成”变为“人工修改”；
- 在“布局优点”下方手动填写 **适用场景、需要避开的坑、禁用场景**（这三块 AI 不会生成）。

### 步骤 6：保存归档
- 点编辑页**右下角悬浮的【保存归档】**（旁边为“返回”），案例写入浏览器本地，并自动生成一条版本记录；
- 点主区右上角 **【导出Markdown】** 可下载与对话分析模板一致的 Markdown（未保存的空案例会提示先保存）。

> **键盘切换**：查看页按 ↑ / ↓ 可按案例顺序跳到上一个 / 下一个案例（在输入框、文本域中打字时不触发）。
>
> **空框隐藏**：查看页右侧只渲染有内容的区块，AI 块、人工块、标注卡、原始数据、缩略图条在为空时
> 都会整框隐藏，无图时主图也不显示裂图占位。

### 步骤 7：对比复盘
打开 `compare.html`，分别选择案例 A、B，即可并排查看图片与全套解析，勾选“同步滚动”可对齐浏览。

## 四、数据存储与 file:// 限制（务必了解）

由于浏览器安全策略，用 `file://` 直接打开页面时：

1. **页面不能直接读取本地 `data/cases.json`**（控制台会报 CORS 错误，属预期现象）。
   因此内置示例通过 `seed.js` 内联加载，运行时数据保存在浏览器 **localStorage**，不影响使用。
2. **上传的图片不会写入 `assets/images` 文件夹**，而是以 Blob 形式保存在浏览器的
   **IndexedDB**（避免 base64 撑爆 localStorage 的 5MB 上限）。清空浏览器数据会导致案例与图片丢失。
3. **恢复方式**：画廊页保留 **【导入JSON】**，可导入此前导出的 `cases.json` 恢复案例（JSON 导出按钮已按要求移除）。
4. `data/cases.json`、`data/promptTemplates.json` 是标准数据文件，供导入与外部程序参考，
   运行时不直接依赖它们。

## 五、接入真实 AI（默认是演示模式）

默认开启**演示模式**：不发真实请求，返回带【演示】前缀的模拟数据，便于无密钥也能走通流程。

接入真实多模态模型（OpenAI 兼容接口）：

1. 打开 `settings.html`，在“AI 视觉接入配置”填写：
   - **接口地址**：`.../chat/completions`（默认火山方舟，可改为任意 OpenAI 兼容端点）；
   - **模型 ID**：视觉模型名称；
   - **API Key**：仅保存在本机浏览器，不会写入任何文件；
2. **取消勾选“演示模式”**，点【保存接入配置】；
3. 在设置页“对案例执行 AI 解析”点【执行 AI 解析】即发起真实请求。

> 注意：`file://` 下部分接口可能因跨域（CORS）策略被浏览器拦截，若遇此情况需用本地
> 静态服务器（如 `python -m http.server`）以 `http://` 方式打开，或使用允许跨域的接口。

## 五（补）、目录授权直写（把内容真正写入本地文件夹）

默认运行时数据只存在浏览器内（localStorage / IndexedDB）。借助 **File System Access API**
（需 Chrome / Edge，设置页会提示当前浏览器是否支持），可把案例与图片直接写入一个本地文件夹：

1. 在 `settings.html`“内容保存路径”点 **【选择并授权目录】**（必须真实鼠标点击，系统会弹目录选择框）；
2. 选择目标文件夹并确认，授权句柄保存在 IndexedDB，刷新后仍有效；
3. 点 **【写入测试文件】** 可验证；点 **【导出全部案例到目录】** 会在该目录生成：
   - `cases/<案例id>.json`：每个案例一份完整 JSON；
   - `images/<案例id>/<原文件名>`：上传的图片（内置示例图不重复落盘）；
4. 点【清除目录】可解除授权。

> 目录选择器只能由用户真实点击触发，脚本无法代替；写入权限在每次会话首次使用时可能需要再次确认。

## 六、数据结构概览（snake_case）

- 案例顶层：`id, title, cover_image_id, images[], style_tags[], business_tags[], favorite, group_id,
  analysis{}, use_cases{}, pitfalls{}, ai_raw_result, ai_meta{}, versions[], created_at, updated_at`
- **分组**：`group_id` 指向分组 id；分组单独存于 localStorage（`uilearn_groups_v1`），
  结构 `[{id, name}]`，内置默认分组 `grp_default`；老案例无 `group_id` 时自动迁移为默认分组；
  分组折叠状态存于 `uilearn_tree_state_v1`
- `analysis` 固定 5 个键：`layout_structure / visual_style / interaction / color_mood / layout_strengths`
- 每个内容块结构：`{content, source, updated_at}`，`source` 取值：
  `ai_generated`（AI生成）、`human_modified`（人工修改）、`human`（纯人工）
- `pitfalls` 含 `avoid_pitfalls`（需要避开的坑）、`forbidden_scenarios`（禁用场景）
- `ai_meta`：`model, template_id, parsed_at, static_note`
- 图片对象：`id, name, src, is_seed, blob_id, data_url, annotations[]`
  标注对象：`id, x, y（百分比）, text, color`

> 字段名为本次统一约定，如你已有既定字段体系，可据此调整 `store.js` 与各页面映射。
