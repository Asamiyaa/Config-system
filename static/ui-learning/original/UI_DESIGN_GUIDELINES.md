# 可复用 UI 设计与优化规范

版本：1.0 · 更新：2026-11-07

适用：Web、移动 H5、管理后台、Dashboard、内容库、编辑工作台与商品详情页。

目的：让页面任务清楚、内容易读、操作可预期、视觉一致。供设计师、开发者与 AI Agent 在新项目和已有项目中使用。

## 1. 使用方法与约束等级

把本文复制到目标项目的 `docs/UI_DESIGN_GUIDELINES.md`，在项目说明或任务中引用。文档不会自动成为所有工具的规则；需要在该项目的工作指令中明确要求遵循。

- **必须**：本项目采用本规范后，默认需要满足的要求。例外需说明原因及替代方式。
- **建议**：优先采用，但允许根据用户任务、设备和既有设计调整。
- **参考值**：启动设计的候选参数，不是合规标准或所有产品的统一答案。

遵循顺序：用户明确需求 → 项目已有品牌、组件与无障碍要求 → 本规范。优化已有项目时，优先复用现有组件和样式变量，不为了统一外观而重做全部界面。

采用前填写：

```text
项目名称：
目标用户与主要设备：
用户进入后的首要任务：
核心业务对象：
本次范围与不可改动项：
已有组件库、字体与品牌规范：
内容规模、长文本和异常数据样例：
关键交互与需要保留的行为：
验收环境与成功判据：
```

## 2. 设计总原则

1. **任务优先**：先明确用户要完成什么，再决定导航、布局和视觉效果。
2. **主次明确**：一个任务区域优先突出一个主要动作；多个独立任务可以各有主动作。
3. **内容驱动**：用真实或有代表性的内容设计，不用短占位文字掩盖布局问题。
4. **一致且有意义**：相同外观表达相同含义；颜色、尺寸、位置都应有用途。
5. **反馈完整**：用户能知道当前状态、操作结果和下一步。
6. **可恢复**：重要修改和破坏性操作提供适当的撤销、确认或恢复方式。
7. **证据明确**：区分实际观察、代码确认、交互实测和设计推测。

设计感来自层级、比例、节奏、一致性与细节准确性。不要把深色、圆角、渐变、玻璃效果或大量卡片直接等同于高质量设计。

## 3. 信息架构与页面任务

每个主要页面必须写清：用户来做什么、首先应看到什么、完成后去哪里。

| 页面 | 首要任务 | 优先内容 | 典型主要动作 |
|---|---|---|---|
| 内容库 / 画廊 | 找到目标内容 | 图片、标题、识别信息、搜索结果 | 查看；按业务需要突出新建 |
| 查看页 | 理解对象并决定下一步 | 主体内容、关键结论、相关证据 | 编辑、处理或继续学习 |
| 编辑页 | 完成并保存修改 | 当前编辑对象、输入、校验与保存状态 | 保存 / 提交 |
| Dashboard | 判断状态并定位问题 | 核心指标、异常、趋势与明细 | 下钻 / 处理 |
| 商品详情 | 理解商品并完成选择 | 图片、价格、规格、服务与库存 | 购买 / 加入购物车 |
| 设置页 | 管理低频偏好与接入 | 配置值、解释、校验与生效状态 | 保存配置 |

要求：

- 必须按用户任务组织内容，不按数据库字段顺序机械排列。
- 高频任务应形成连续流程，避免在设置页与工作页之间反复跳转。
- 建议把服务配置留在设置页，把执行动作放在实际工作场景中。
- 导航必须能识别当前所在位置；关键入口不能仅依赖悬停显现。
- 隐藏空区块前，判断用户是否需要知道其为空。必填、待处理、加载失败不能伪装成不存在。

## 4. 布局、密度与响应式

### 4.1 布局规则

- 必须建立稳定的对齐线：标题、正文、表单、按钮和卡片边缘有一致关系。
- 相关内容靠近，不同任务之间增加间距；不要给每段内容都套卡片。
- 卡片用于独立对象或任务分组，内部优先用标题、间距、分隔线表达层次。
- 留白必须有助于阅读和聚焦，避免控制区占满宽度而核心内容过小。
- 默认使用清晰的主滚动区域；分栏独立滚动仅在对照、编辑等确有需要时采用。
- 固定、吸顶或吸底区域必须为正文预留空间，不能遮挡最后一项内容或聚焦控件。

### 4.2 参考参数

| 项目 | 新项目参考值 | 使用说明 |
|---|---|---|
| 间距序列 | 4 / 8 / 12 / 16 / 24 / 32 / 48px | 优先复用既有序列 |
| 正文 | 14–16px | 根据内容密度、设备和字体调整 |
| 正文行高 | 1.5–1.7 | 表格与大标题单独设置 |
| 控件圆角 | 6–10px | 避免不同组件任意变化 |
| 面板圆角 | 10–16px | 与品牌风格保持一致 |
| 常规触控区域 | 约 44×44px 或更大 | 作为易操作性目标；图标可小于点击区域 |

这些值不是强制视觉模板，也不代表通过无障碍验收。

### 4.3 响应式规则

- 断点由内容是否能合理展示决定，不照搬某个项目的 900px 等阈值。
- 窄屏应重排信息优先级，不能只是按比例缩小桌面页面。
- 筛选项较多时，可收纳为抽屉或折叠区，并显示已选条件与结果数量。
- 宽表格可在明确的局部区域横向滚动；普通正文不应导致整页横向滚动。
- 手机底部固定操作需考虑安全区域；输入时验证软键盘不会遮挡输入和提交动作。
- 图片加载前保留合理宽高比，避免加载后把正在点击的内容推走。

## 5. 视觉系统与设计感

### 5.1 建立语义化样式变量

至少定义背景、面板、主文字、次文字、边框、主操作、成功、警告、错误、焦点样式，以及间距、圆角、阴影和动效参数。

```css
/* 示例命名；具体值使用目标项目的设计体系 */
/* --color-background, --color-surface, --color-text-primary */
/* --color-text-secondary, --color-border, --color-action-primary */
/* --color-success, --color-warning, --color-error, --color-focus */
/* --space-*, --radius-*, --shadow-*, --duration-* */
```

### 5.2 字体、颜色与层次

- 必须区分页面标题、区块标题、正文、辅助信息，组合使用字号、字重、间距和颜色。
- 主色集中服务主要行动和选中状态；告警色表达业务含义。
- 状态不能仅靠颜色区分，还需文字、图标或形状。
- 次要文字也必须可读，不能用极浅灰色换取所谓简洁感。
- 数字按需求统一单位、小数位、分组方式；需纵向比较时采用合适的等宽数字。
- 阴影用于区分层次和浮层，避免所有容器都使用强阴影。
- 深色主题必须单独验证文字、边界和状态的可辨识程度；不能简单反转颜色。

### 5.3 图片和内容

- 图片主导的页面必须让用户看清主要材料，而非让筛选和装饰占据中心。
- 截图分析、证据图和图表默认保留完整内容；封面裁切必须避免丢失关键识别信息。
- 查看原图提供可发现的入口，双击或手势只作为补充。
- 正文长度应适合持续阅读，避免在超宽屏上无限拉长一行。
- 真实图片、准确文案和恰当的数据往往比额外视觉效果更能提升完成度。

## 6. 动态交互与反馈

### 6.1 必须考虑的状态

按组件用途覆盖：默认、悬停、键盘聚焦、按下、选中、禁用、加载、成功、失败、空内容。无需给不适用的组件机械增加全部状态。

| 场景 | 设计要求 |
|---|---|
| 搜索 / 筛选 | 展示当前条件和结果数量；无结果时提供清除或调整入口 |
| 异步请求 | 提供进行中反馈，防止重复提交，失败允许重试并保留用户输入 |
| 保存 | 区分未保存、保存中、已保存和保存失败；失败不能显示成功 |
| 删除 / 覆盖 | 按影响程度提供撤销、确认或恢复；说明受影响对象 |
| 拖拽 | 展示可拖动性、目标区域和放置结果；提供非拖拽替代操作 |
| 上传 | 展示进度或处理状态、错误原因；允许移除或重试 |
| 弹窗 / 抽屉 | 提供关闭方式；管理焦点，关闭后恢复焦点，必要时锁定背景滚动 |
| 选项切换 | 同步更新有关内容和状态，保留合理的阅读位置 |

禁用控件时必须有可理解的原因；对必须先完成某项条件的操作，可展示邻近说明。

### 6.2 动效规则

- 动效应解释状态、空间关系或操作结果。
- 小型反馈可从 120–200ms、面板展开可从 180–280ms 起步调试；这些是参考值。
- 避免无意义循环、连续闪烁和数据刷新时大面积位移。
- 尊重减少动态效果的用户偏好，覆盖抽屉、灯箱、提示、卡片等实际动效。
- 鼠标悬停反馈必须有触屏和键盘对应方案。
- 动效结束前后，焦点、点击区域和布局必须保持可靠。

## 7. Dashboard 专项规范

### 7.1 必须回答的四个问题

1. 当前情况如何？——关键指标、单位、统计范围。
2. 哪些变化值得关注？——异常、变化幅度、目标差距。
3. 为什么变化？——趋势、拆分比较、可查证明细。
4. 下一步做什么？——下钻、筛选、处理或关联任务。

### 7.2 指标与图表

- 指标应按业务重要性排序，不为填满栅格增加无关指标。
- 关键指标明确名称、数值、单位、时间范围；有比较时说明比较对象。
- 对时效敏感的数据提供更新时间、加载失败和过期状态。
- 缺失数据、零值、尚未加载与请求失败必须区分。
- 上升或下降的颜色取决于业务含义；错误率上涨不能标为成功。
- 趋势优先考虑折线，类别比较考虑条形，精确查询考虑表格；最终选择由问题决定。
- 图表必须有足够的轴、单位、图例和口径信息，避免截断刻度制造误导。
- 数值悬浮提示不能成为唯一信息入口，应考虑点击、键盘或数据表替代。

示例文案（虚构数据）：

```text
今日订单 1,284
较昨日同期 +8.2% · 今日目标完成 76%
更新于 14:32
```

### 7.3 工作流

- 全局时间和筛选条件应保持可见，并清楚说明影响范围。
- 下钻后保留时间、筛选和来源上下文；返回后尽量恢复位置。
- 自动刷新不应打断选择、编辑或阅读，也不应悄悄清除用户条件。
- 监控型、分析型和操作型 Dashboard 的主次不同，不能全部套用同一组卡片。

## 8. 内容库、编辑器与 AI 工作台专项规范

- 内容库突出图片、标题与少量有效识别信息，筛选工具的占用应与数据规模匹配。
- 编辑页支持对照原始材料；必要时提供可调整分栏或专注模式。
- 重要编辑状态应持续可见，不能仅靠短暂提示说明是否保存。
- AI 结果应标明来源与待确认状态，避免让用户误认为已验证事实。
- 局部重生成应明确影响范围；覆盖人工修改前提供适当保护和恢复方式。
- 长时间任务提供状态和失败恢复；取消能力应根据实际请求能力实现，不能只隐藏进度假装取消。
- 对比页优先支持同章节对齐。内容长度不同时，直接同步滚动像素不能保证语义对齐。
- 图片标注使用相对位置，并在缩放后验证标注与内容仍对应。

## 9. 移动商品详情专项规范

- 按购买决策组织内容：商品识别 → 价格与权益 → 规格 → 服务信息 → 购买操作。
- 规格选择后同步更新价格、库存、图片和按钮状态中受影响的部分。
- 底部操作栏为正文和系统安全区域预留空间。
- 不可购买时提供准确原因和可行下一步，避免仅显示一个灰色按钮。
- 实际商品图片、价格、配送及售后文案必须参与排版验证。
- 商品页的低密度展示逻辑不能直接移植到需要多维比较的后台工作台。

## 10. 无障碍与健壮性

- 关键任务必须可以用键盘完成，焦点清楚、顺序合理，无意外焦点陷阱。
- 图标按钮具有可访问名称；表单有明确标签，错误与相应字段关联。
- 使用正确的按钮、链接和表单语义，不用不可操作的容器假装交互控件。
- 图片根据用途提供替代文本；装饰图片避免制造重复朗读。
- 文字缩放、较大系统字体和窄视口下验证内容与操作仍可用。
- 根据项目要求验证适用的无障碍标准，不以本规范的参考参数代替正式检查。
- 网络失败、部分数据失败、超长文本、空列表和大量数据都必须有可理解的呈现。

## 11. 新项目执行流程

1. 填写任务简表，明确用户、设备、业务对象和成功判据。
2. 列出页面结构与主流程，包括加载、失败和恢复路径。
3. 收集代表性内容，确定信息优先级与布局。
4. 建立或复用设计变量与基础组件。
5. 完成一个关键页面和完整任务流程，再扩展到其他页面。
6. 验证桌面、窄屏、长内容、空内容和错误状态。
7. 记录实际验证结果、限制和待解决问题。

## 12. 已有项目优化流程

### 12.1 先收集证据

- 阅读项目规范、样式变量、组件和关键流程代码。
- 检查当前页面，历史截图仅作辅助，不直接当作当前缺陷。
- 记录问题触发条件、用户影响和证据，再提出修改。
- 保留合理的信息架构和成熟交互；没有明确理由不更换技术栈、路由和组件库。

### 12.2 优先级

| 等级 | 优先处理 | 例子 |
|---|---|---|
| P0 | 无法完成任务、数据或结果不可靠 | 保存失败却提示成功、关键按钮无法操作 |
| P1 | 严重阅读与操作障碍 | 内容被遮挡、窄屏溢出、键盘无法访问核心操作 |
| P2 | 效率与层级问题 | 主要内容过小、任务频繁跨页、筛选信息不清楚 |
| P3 | 视觉一致性与精细调整 | 间距不统一、局部圆角或阴影不一致 |

### 12.3 分批改动

优先修复任务与布局，再优化主次、状态和视觉细节。每批说明修改理由、影响范围和验证结果，避免大范围视觉重写掩盖行为回归。

问题记录模板：

```text
页面 / 组件：
问题与触发条件：
证据类型：截图观察 / 代码确认 / 交互实测 / 待验证推测
用户影响：
优先级：
建议改动与需保留行为：
验收方式：
验证结果与剩余限制：
```

## 13. 验收清单

按本次范围选择适用项；不适用的项注明原因。未经验证的项标为待验证，不默认通过。

- [ ] 页面首要任务、主要内容与主操作清楚。
- [ ] 导航当前位置、返回路径和筛选范围可理解。
- [ ] 内容层级与对齐一致，没有不必要的嵌套卡片。
- [ ] 真实图片、长标题、长正文和大量数据能合理展示。
- [ ] 图片加载有空间预留，必要时能查看完整原图。
- [ ] 窄屏无非预期整页横向滚动，固定区域不遮挡内容。
- [ ] 加载、空内容、失败、成功和未保存状态合理。
- [ ] 重要修改不会因返回、覆盖或重复提交而意外丢失。
- [ ] 键盘、焦点、触屏和弹层行为可用。
- [ ] 状态不只依赖颜色，文字和控件有足够辨识度。
- [ ] Dashboard 指标口径、单位、时间和缺失状态明确。
- [ ] 动效有用途，并支持减少动态效果偏好。
- [ ] 关键流程已实测，截图附有页面、视口、状态与版本背景。

建议验收记录：

| 页面 / 流程 | 环境与状态 | 检查结果 | 证据 | 剩余问题 |
|---|---|---|---|---|
| 示例：编辑并保存 | 桌面、长文本 | 待验证 | 待补充 | 待补充 |

## 14. 可直接交给 AI Agent 的任务模板

### 新建界面

```text
请阅读并遵循 docs/UI_DESIGN_GUIDELINES.md，以及本项目已有规范。
目标用户：[填写]
主要任务：[填写]
页面与关键流程：[填写]
参考内容与设计约束：[填写]

先检查已有组件、样式变量和实现方式，再完成界面。
用有代表性的真实内容确定信息层级；补齐适用的加载、空内容、失败、
成功和交互状态，验证响应式和键盘操作。
不要为了视觉效果自行增加无关功能或更换技术栈。
交付时说明设计决策、修改文件、实际验证与未验证项。
```

### 优化已有项目

```text
请依据 docs/UI_DESIGN_GUIDELINES.md 优化以下范围：[填写]。
优先解决的问题：[填写]
```
