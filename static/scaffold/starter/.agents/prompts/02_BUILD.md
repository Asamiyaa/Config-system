# Prompt 02 — 高保真实现

根据项目的 AGENTS.md、UX_FOUNDATIONS.md、DESIGN_SYSTEM.md、MOTION_SPEC.md、INTERACTION_BLUEPRINT.md 执行。

要求：
- 先识别现有技术栈、页面状态、现有依赖；绘制前三个核心操作路径，防止功能堆砌和信息过载。
- 统一全站 UI 规范；优先消除多层菜单和无反馈按钮，常见核心操作尽量 2～3 次操作可达。
- 不要为了视觉效果破坏可用性、数据真实性、既有路由/API。
- 动效只能由用户明确交互触发：禁止默认加载自动入场、漂浮呼吸、无意义滚动动画。
- 展开/收起同一个共享元素，严格配对锚点、形变路径、时长与缓动；反向从当前位置继续。
- 使用物理感非线性缓动，主容器先于子内容，小幅精密按压/开关/校验反馈，无夸张弹跳。
- 将重要动效抽成可中断、可清理、可复用的状态/时间轴。
- 有必要时使用 Three.js/GSAP，没必要时优先使用 CSS/原有动画库。
- 实现响应式、键盘操作、focus-visible 和 reduced-motion。
- 实际启动程序，操作核心路径、验证等待/完成/失败反馈及反向收起，捕获截图，修复明显视觉/交互问题。
- 最终提供文件变更、命令、实际验证证据和未完成项。

不要仅产出静态截图；交互必须可真实运行。

**场景库 v2.0：** 在任何交互任务开始前阅读 `.agents/scenarios/AUTO_SELECTION.md`，用 `python tools/pick_scenario.py "任务"` 选 1 主 + 最多 2 辅，完整遵循专属场景的时间/状态/异常/验收要求。原 01/02/03 精确参数继续有效；禁止将其强加到其它场景。
