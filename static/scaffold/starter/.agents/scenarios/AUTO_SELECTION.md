# Codex 自动选择交互配方（按需求，而非按库）

## 触发方式

**任何 UI / 前端 / 动效 / 交互任务，都先完成以下选择步骤。** 此配方库的范围是常见高级交互，并非所有可能交互的封闭全集；新增业务类型请沿 `../design/SCENARIO_PROMPT_SCHEMA.md` 创建新契约。

### 第一步：识别用户的主任务

从需求中提取：操作对象、入口、结束状态、是否有业务请求、是否可撤销、现有技术栈/框架和平台。**不允许单凭“炫酷、丝滑、Opus风格”选 3D**。

### 第二步：在项目根目录执行场景搜索

```sh
python tools/pick_scenario.py "点击卡片从原位展开详情弹窗"
python tools/pick_scenario.py "拖拽排序任务卡片"
python tools/pick_scenario.py "图表切换数据集的连续过渡"
python tools/pick_scenario.py "时间轴拖动控制三维摄像机"
python tools/pick_scenario.py "命令面板 Ctrl+K"
```

也可以直接读 `INDEX.md`，或者通过 `--list` 查看所有条目。CLI 仅提供**关键词匹配**而非大语言模型语义理解，结果要人工检查；不能将排名分数解释为实现难度或质量分数。

### 第三步：选 1 主 + 至多 2 辅

- 主场景决定唯一业务状态、用户入口、核心时间轴。
- 辅助场景只完善反馈/可访问性/布局，不重新控制核心元素的位置、opacity 或 transform。
- 主/辅场景规则冲突时：**真实性和可达性 > 业务正确性 > 共享几何连续性 > 装饰与节奏**。优先保留真实功能。

## 推荐搭配

| 任务 | 主场景 | 可选辅助 | 冲突提醒 |
|---|---|---|---|
| 卡片长成弹窗 | 13 | 03, 78 | 避免同时为同元素使用 View Transition 与 Motion |
| 列表跳详情 | 01 | 03, 80 | 路由状态和转场必须同步提交 |
| 左栏展开收起 | 12 | 05, 103 | 宽度变化时保护正文，不进行装饰性缩放 |
| 任务列表拖拽 | 33 | 102, 78 | 拖动跟手，不延迟坐标 |
| 图表数据切换 | 44 | 49, 81 | 只有真实数据变化能驱动指标含义 |
| 流式行情 | 47 | 52, 81 | 流式事件不需要“倒放业务数据” |
| 历史回放时间轴 | 62 | 55, 52 | Replay 与 Live 状态必须明确隔离 |
| 3D 户型沙盘 | 66 | 65, 69 | 无尺寸不能宣称真实 1:1 |
| Cmd/Ctrl+K | 86 | 87, 101 | focus、Esc、权限优先于过渡 |
| 移动端抽屉 | 15 | 99, 104 | 手势与系统滚动冲突时保留原生体验 |

## Codex 输出格式

```text
选择的主场景：编号 / 名称 / 为什么
选择的辅助场景：编号 / 名称 / 为什么（最多两个）
不采用的炫技效果：说明避免的成本、信息负担和冲突
现有技术栈与受控状态：实际仓库文件证据
主场景运动契约：触发 → 起点 → 终点 → 时序 → 反向 → 取消 → 降级
实施文件：实际修改列表
真实验证：测试命令、浏览器/视口、截图、失败及未测试项
```
