# 多配方组合冲突控制

## 一条属性只有一个动画控制源

当一个元素同时涉及 shared element、hover、drag、scroll、camera 等动效时，确定**唯一的**变换控制器，不允许 GSAP、Motion、CSS transition 与 WAAPI 同时写入同一 `transform`。实在要组合，使用不同嵌套层：外层控制布局迁移，内层控制短幅按压，并明确恢复时机。

## 统一状态模型

- 业务状态：真实请求/选择/权限/已保存版本；不可随意回滚。
- 交互状态：idle / manipulating / committing / error / cancelling。
- 视觉进度：0..1（可中断、反向），不可作为业务真实性来源。
- 焦点与历史：单独保存 restore target / URL / scroll anchor。

主场景确定业务真值，辅助场景不得覆盖。动效被跳过时业务也必须完整完成。

## 可逆 ≠ 所有动作都能倒放

对于展开/收起、进入/退出、选择/撤销，严格使用同源路径、时长、缓动，并可在中途反向。

对于网络成功、删除已提交、行情推送、文件下载，不能假装业务过程可以反向；视觉上可以平稳变为新状态，但执行业务撤销需要真实 API / 事务。

## 主动触发与数据反馈

禁止自动首页入场、常驻呼吸、永远旋转的粒子。用户主动“开始监控”后出现的真实状态变化、请求返回/错误反馈允许必要的微变化；不过度重绘。

## 五层降级优先级

1. 正确业务语义、焦点、键盘、加载和 URL
2. reduced-motion 静态可用
3. CSS/浏览器原生过渡
4. 现有动画库或 WAAPI/FLIP
5. 大体量 WebGL/Three.js 仅在真实空间信息需要时

## 性能红线

- 避免每帧 layout read + write 循环；测量起止位置并以 transform 变换。
- 无限列表应使用虚拟化，不对几万行制造逐项动画。
- 3D 渲染循环只有在视图可见且用户实际需要时运行；释放贴图、几何体和监听。
- 同时多个动画最多共享一个 RAF 调度器；组件卸载必须清理定时器与请求。

## 组合验收

- 主场景独立工作，再叠加辅助，逐步检查状态、反向、键盘/触控/无障碍。
- 在 40% 进度中断/反向；断网/取消后恢复；打开两个同类浮层确认堆栈策略。
- 输出前后截图与真实 DOM 几何/业务状态日志，不允许只靠“看起来丝滑”。
